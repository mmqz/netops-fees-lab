# ADR 0006 — API 响应一律 `Cache-Control: no-store`

日期：2026-10-09
状态：已接受（终审阶段发现并修复）

## 背景

终审浏览器冒烟测试中发现：全新空数据库启动的服务器，页面概览却显示完整数据（64 资源 / 评分 32 / E13W3I1）。排查链路：

1. 服务器日志中**没有**页面数据请求的记录；
2. 杀掉服务器后，页面上下文 `fetch('/api/stats')` 依然返回旧数据；
3. 数据库文件确认为空。

结论：HTTP 客户端（浏览器）**磁盘缓存**了早期 UI 开发会话（8092 端口曾由一次被中断的开发自测使用并导入了完整数据）中的 `GET /api/stats` 响应。当时的响应**没有任何 `Cache-Control` 头**，浏览器按 RFC 9111 的启发式新鲜度（heuristic freshness，取响应年龄的 10%）直接复用了缓存副本，导致后续同源同 URL 的请求不再到达服务器。

## 决策

1. 所有 `/api/*` 响应在中间件层统一注入 `Cache-Control: no-store`（含 404 信封与错误响应）。这些端点全部是动态数据库视图，可缓存性为零。
2. SPA 的 `index.html` 与客户端路由回退维持 `no-cache`（每次需向服务器再验证）；带内容哈希的静态资源（`/assets/*`）保持默认可缓存。
3. 回归测试：`TestAPIHealthAndSPA` 断言 `/api/health` 响应头为 `no-store`。

## 影响

- 页面数据永远反映真实数据库状态，杜绝"幽灵统计"。
- 每次页面加载都会真实请求 API（本应用为本地单用户工具，性能影响可忽略）。
- 测试与演示环境必须使用干净的浏览器会话（agent-browser 独立 session），避免旧会话缓存干扰判断。

## 教训

动态 JSON API 不发缓存头 ≠ 不缓存——默认行为是启发式缓存。所有动态端点必须显式声明缓存策略。
