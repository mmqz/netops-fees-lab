# 综维费用明细字段定义（v1 → v2 修订见文末）

> 用途：系统表之外的「明细层」，人工补录，**不参与金额计算，仅作佐证**
> 依据：从 7 份真实绩效单的 71 条明细归纳得出（v1）；#16 完成线第 6 条修订（v2）
> 设计原则：**明细不作为权威数据**，与系统表的差异只提示、不改数
> **本文档是「字段建议，非强制」**（#16 §4 原文）——实现按 v2 修订执行

---

## 一、为什么要单独做明细层

### 系统表（工资单.xls）能回答的

| 能回答 | 不能回答 |
| --- | --- |
| 某人某月发了多少钱 | 这笔钱花在什么事上 |
| 各科目合计是否正确 | 费用属于哪个类别 |
| 应发/实发/单位成本 | 对应哪个工单/抢修 |
| 和智慧人力是否对齐 | 有没有重复或冲销 |

### 缺口量化（实测）

```
系统表「1.8 其他」总额:      36,438.60 元  (占应发 29.1%)
可追溯到绩效单明细的部分:     15,585.70 元  (42.8%)
无任何来源的部分:            20,852.90 元  (57.2%)
```

**明细层的目的：把这个 57.2% 逐步补齐，但不能假装它是准确的。**

## 二、核心原则：分层可信

```
┌────────────────────────────────────────────┐
│ 系统表（权威）★ ★ ★ ★ ★                    │
│   来源：智慧人力系统导出                    │
│   用途：金额计算、成本核算、对账             │
│   规则：7 项内部校验全部通过才能入账          │
│   缺失：无明细，无法解释金额构成              │
└────────────────────────────────────────────┘
                    ↓ 按 工号 + 账期 关联
┌────────────────────────────────────────────┐
│ 明细表（参考）★ ★ ★ ☆ ☆                    │
│   来源：县区绩效单 → 人工逐条补录            │
│   用途：解释金额构成、发现异常、追溯依据       │
│   规则：格式不统一，人工核对，标注「待核实」    │
│   约束：**永不参与金额计算**                  │
└────────────────────────────────────────────┘
```

### 铁律

| # | 铁律 | 理由 |
| --- | --- | --- |
| 1 | 明细**不能覆盖**系统表金额 | 系统表是系统算的，明细是人填的 |
| 2 | 明细与系统表**不一致时只提示** | 可能是明细错，也可能是系统表待解释 |
| 3 | 每条明细**必须标注录入人+录入时间** | 人工数据要有来源 |
| 4 | 明细**默认状态为「待核实」** | 需人工确认后才标记可信 |
| 5 | 同一笔明细**不允许重复关联** | 避免重复计数 |

## 三、明细表字段定义

### 3.1 必填字段（`detail_required`）

| 字段 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `detail_id` | TEXT PK | 主键 | `fd_<uuid>` |
| `staff_code` | TEXT NOT NULL | 工号（关联系统表） | `W8522883` |
| `period` | TEXT NOT NULL | 账期 YYYYMM（关联系统表） | `202609` |
| `category` | TEXT NOT NULL | **费用类别**（见 3.2） | `低值易耗品` |
| `amount` | INTEGER NOT NULL | 金额（分，可为负=冲销） | `23523` |
| `occurred_on` | TEXT | 发生日期 YYYY-MM-DD | `2026-09-17` |
| `status` | TEXT NOT NULL | 核实状态（见 3.4） | `pending` |
| `created_by` | TEXT NOT NULL | 录入人 | `zhangsan` |
| `created_at` | TEXT NOT NULL | 录入时间 | `2026-10-26T10:00:00Z` |

### 3.2 费用类别（`category`）—— 闭集

**从真实数据归纳，共 12 类：**

| 值 | 中文 | 实测条数 | 典型项目 |
| --- | --- | --- | --- |
| `transfer_fiber` | 划转纤芯绩效 | 多 | 划转纤芯绩效 |
| `piece_rate` | 计件工资 | 3 | 跨道光缆直埋引下计件工资 |
| `meal_allowance` | 加班餐补 | 多 | 抢修加班餐费补贴 |
| `lodging` | 住宿费 | 4 | 抢修住宿3人1晚 |
| `consumables` | 低值易耗品 | 多 | 卡钉、锤子、胶带、铁丝、手套 |
| `tools` | 维修工器具 | 多 | 红光笔、米勒钳、光功率机、分光器 |
| `fuel` | 油费 | 2 | 9月10加油 |
| `vehicle_repair` | 车辆维修 | 3 | 修空调、扒胎换胎、换机油 |
| `certification` | 资质培训 | 1 | 电工证报名费 |
| `line_relocation` | 线路改迁 | 1 | 线路改迁 |
| `perf_allocation` | 绩效分配 | 1 | 绩效分配 |
| `write_off` | 冲销 | 2 | 冲销上月多报费用 |

**扩展规则**：新增类别需同时更新此表 + 校验测试，不允许自由填写。

### 3.3 选填字段

| 字段 | 类型 | 说明 | 为什么要 |
| --- | --- | --- | --- |
| `item_name` | TEXT | 原始项目名（照抄绩效单） | 保留原文，便于人工核对 |
| `quantity` | REAL | 数量 | 从原文提取，如「30米」「4个」 |
| `unit_price` | INTEGER | 单价（分） | 从原文提取，如「*5」 |
| `quantity_unit` | TEXT | 单位 | 米/个/晚/人 |
| `reason` | TEXT | 事由 | 抢修/例行维护/故障处理 |
| `location` | TEXT | 地点/线路 | 如「兴华至韩家园光缆」 |
| `work_order_no` | TEXT | 关联工单号 | 能关联到工作量 |
| `invoice_no` | TEXT | 发票号 | 财务凭证 |
| `counterparty` | TEXT | 供应商/收款方 | 在哪买的 |
| `source_file` | TEXT | 来源文件名 | 追溯原始表 |
| `source_row` | INTEGER | 原表行号 | 精确追溯 |
| `remark` | TEXT | 备注 | 特殊情况说明 |

### 3.4 核实状态（`status`）

| 值 | 含义 | 谁能改 |
| --- | --- | --- |
| `pending` | 待核实（**默认**） | — |
| `confirmed` | 已核实 | 审核人 |
| `rejected` | 已驳回 | 审核人 |
| `unmatched` | 无系统表对应 | 系统自动 |

**状态流转**：

```
录入 -> pending --核实--> confirmed
           |
           +--驳回--> rejected（需填驳回原因）

系统自动标记：
  明细总额 != 系统表对应科目 -> 差异标记（不改状态）
  系统表有金额但无任何明细 -> 该笔标记 unmatched
```

### 3.5 审计字段

| 字段 | 说明 |
| --- | --- |
| `verified_by` | 核实人 |
| `verified_at` | 核实时间 |
| `reject_reason` | 驳回原因 |
| `linked_batch` | 关联的系统表批次号（如 `zw20261022152534-904879_2026-09`） |

## 四、表结构（SQL）

```sql
CREATE TABLE fee_detail_lines (
    detail_id     TEXT PRIMARY KEY,
    staff_code    TEXT NOT NULL,
    period        TEXT NOT NULL,              -- YYYYMM
    category      TEXT NOT NULL,              -- 闭集，见 3.2
    amount_cents  INTEGER NOT NULL,           -- 分，负数=冲销
    occurred_on   TEXT,
    item_name     TEXT,                       -- 原始项目名
    quantity      REAL,
    quantity_unit TEXT,
    unit_price_cents INTEGER,
    reason        TEXT,
    location      TEXT,
    work_order_no TEXT,
    invoice_no    TEXT,
    counterparty  TEXT,
    source_file   TEXT,
    source_row    INTEGER,
    remark        TEXT,
    status        TEXT NOT NULL DEFAULT 'pending',
    created_by    TEXT NOT NULL,
    created_at    TEXT NOT NULL,
    verified_by   TEXT,
    verified_at   TEXT,
    reject_reason TEXT,
    linked_batch  TEXT,
    CHECK (category IN (
        'transfer_fiber','piece_rate','meal_allowance','lodging',
        'consumables','tools','fuel','vehicle_repair',
        'certification','line_relocation','perf_allocation','write_off'
    )),
    CHECK (status IN ('pending','confirmed','rejected','unmatched'))
);

CREATE INDEX idx_detail_staff_period ON fee_detail_lines(staff_code, period);
CREATE INDEX idx_detail_category ON fee_detail_lines(category);
CREATE INDEX idx_detail_status ON fee_detail_lines(status);
```

## 五、与系统表的关联校验

### 5.1 关联键

```
明细.staff_code + 明细.period  ->  系统表.工号 + 系统表.业务账期
```

### 5.2 校验规则（只提示，不改数）

| 规则 | 判定 | 提示 |
| --- | --- | --- |
| **明细有、系统表无** | 找不到对应人员/账期 | 警告：明细无法关联 |
| **系统表有、明细无** | 系统表 1.8其他 > 0 但无明细 | 提示：该笔无明细依据 |
| **金额不一致** | Σ明细 ≠ 系统表 1.8其他 | 提示差额，双方都列出 |
| **类别缺失** | category 为空 | 阻止保存（必填） |
| **重复关联** | 同一条明细被多处引用 | 阻止保存 |

### 5.3 展示规则

```
[系统表 1.8其他]  2,413.95
  ├── 划转纤芯绩效      428.72  [已核实]
  ├── 计件工资        1,500.00  [已核实]
  ├── 工器具            235.23  [待核实]
  ├── 加班餐补          152.00  [已核实]
  └── 低值易耗品         69.00  [待核实]
  ──────────────────────────────
  明细合计 2,384.95   差 -29.00  ⚠ 待补充
```

## 六、录入方式：**逐条手工录入**

### 为什么不做批量导入

| 原因 | 说明 |
| --- | --- |
| 格式不统一 | 7 份表 3 种写法（填金额列 / 填合计列 / 写在文字里） |
| 项目名不规范 | 「9月30日老修古里机站光缆钢角线30米*5=150元…」一句话含 6 类信息 |
| 存在重复 | 同一笔费用在新林两份表里各出现一次 |
| **不可信** | 县区填报本身可能有误 |

**结论：批量导入会把错误结构化。宁可慢，也要人工确认。**

### 录入界面要素

| 区域 | 内容 |
| --- | --- |
| 左侧 | 系统表该人该期金额（**只读**，供对照） |
| 中间 | 明细列表（可增删改） |
| 右侧 | 实时差额（Σ明细 − 系统表金额） |
| 底部 | 类别下拉 / 金额输入 / 日期选择 / 来源文件 |

**关键交互**：

1. 录入时自动从原始文字**建议提取**日期/金额/数量（正则辅助，人工确认）
2. 类别必须从下拉选，不能自由填
3. 保存后自动重算差额并高亮
4. 差额不为 0 时，**允许保存但标记醒目**

## 七、验收标准

1. 明细表可增删改查，字段符合 §3；
2. `category` 必须是闭集之一，非法值被拒；
3. `amount_cents` 用整数分，**不用浮点**；
4. 明细**不影响**系统表任何金额；
5. 明细与系统表差额可实时查看，不一致时醒目提示但不阻断；
6. 每条明细可追溯来源文件 + 行号；
7. 状态流转留痕（谁核实、何时、什么原因驳回）；
8. 提供「无明细的系统表金额」清单，便于补齐。

## 九、v2 修订（#16 完成线第 6 条——实现口径）

v1 起草于主仓费用域拆分之前，口径针对综维工资单一景。#16 把明细层定为**通用录入能力**并明示「参考规格：docs/fee-detail-schema.md（字段建议，非强制）」。实现按以下修订执行，v1 章节保留为字段建议与背景：

| 项 | v1 | v2（#16 口径） | 落地 |
| --- | --- | --- | --- |
| 关联键 | `staff_code + period`（工资单一景） | **`link_key + period + fee_type` 通用三键**——link_key=站址编码或工号（「这笔钱属于谁」），fee_type 定界费用类型 | `fee_detail_lines` 表 |
| 分类 | 12 值**闭集**，不允许自由填写 | **建议集 + 本地自建**——系统提供 12 类默认建议（UI 下拉预填），本地可扩展自定义分类；后端只强制非空，不强制闭集（#16：「提供分类建议，但允许本地自建分类」） | category 自由文本 + UI 建议集 |
| 录入方式 | 逐条手工录入（不做批量导入） | 同 v1——**批量导入会把错误结构化**；正则辅助提取消后做 | HTTP 表单 + CLI |
| 强制项 | — | **三件事**：关联键 + 金额 + 录入留痕（created_by/created_at）；其余全部可选不阻断 | 服务层校验 |
| 差额 | 与系统表 1.8其他 比对 | 与**该 link_key+period+fee_type 的系统表（Parquet 分析层）金额**比对；差额只提示不阻断；默认构建无引擎时差额侧诚实缺席 | reconcile 查询 |
| 状态 | pending/confirmed/rejected/unmatched | 同 v1 三态人工流转 + 留痕（verified_by/verified_at/reject_reason）；unmatched 由人对账标记（系统不自动改状态） | status 变更走审核通道 |
| 精度 | INTEGER 分 | 同——**整数分契约（#65 P1-a）贯穿**，负数=冲销 | amount_cents int64 |
