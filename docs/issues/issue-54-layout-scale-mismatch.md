## 二、缺陷 B：**未修复**——真实根因是各图层布局尺度不统一

### 2.1 云端修了什么（都是对的，但只治了表）

v0.11.1 把 fit 基准从 `elements().boundingBox()` 改成
`fullGraphBoundingBox()`（手工聚合全部节点，绕开 `display:none` 排除），
并加了 letterbox 护栏。**这个改动本身正确**——实测包围盒确实从
`813×1113` 恢复到了 `1893×1223`。

**但包围盒变大不等于内容铺开。** 以下是修复后的实测：

```
[DEFAULT] bbw=1893  bbh=1223  zoom=0.46
[DEFAULT] 像素利用率 util=66.1%  spanX=870
[DEFAULT] GRID:
  [[0,   0,   99, 118,  46, 44, 47,  0],   ← 第 0、7 列空
   [0,  90,  138,   0,   0,  0,  0,  0],
   [0, 446,  819,   0,   0,  0,  0,  0],
   [0,1394, 2566,   0,   0,  0,  0,  0],   ← 第 3~6 列几乎全 0
   [0,1556, 2948,  32,   0,  0,  0,  0],
   [0,1109, 2771,   2,   0,  0,  0,  0],
   [0, 112,  594,   0,   0,  0,  0,  0],
   [0,  50,   48,  50,  31,  0,  0,  0]]
```

**第 2 列有 2,948 个像素，第 3 列只有 32 个。** 内容重心严重偏左，
右侧 5 列基本是空的。

### 2.2 真实根因：五个图层用五套互不相干的坐标尺度

CDP 逐层测量各图层的**布局坐标跨度**（同一时刻、同一画布）：

| 图层 | 节点数 | 宽度 w | 高度 h | 宽高比 |
| --- | --- | --- | --- | --- |
| body（133 台设备本体） | 133 | **447** | 581 | 0.77 |
| L4 接入 | 36 | 661 | 841 | 0.79 |
| **L0 空间** | **21** | **1902** | 1284 | 1.48 |
| L5 逻辑 | 16 | 600 | 527 | 1.14 |
| L6 业务 | 26 | 839 | 1128 | 0.74 |

**21 个 L0 节点（14 个人井 + 7 根电杆）铺开了 1902 的宽度，
而 133 台真实设备只占 447。**

全图包围盒被 L0 这一层单独撑到 1902 宽 → `fit` 按 1902 算 zoom=0.46 →
**真正承载运维信息的 211 个节点（设备+L4/L5/L6）全被压在左侧 1/4，右侧 2/3 是空的。**

### 2.3 为什么 v0.11.1 的"L0 改默认开"是错的方向

云端修复说明里写：

> 默认图层组合 L0 改默认开：L0 空间锚点承载真实地理宽度
> （issue 交叉验证：开 L0 后 bbw 813→1888），14px 无标签暗点视觉成本近零，
> 默认视图可见内容横向利用率 ~33% → 72.1%

**这个推理链断在第二步。** `bbw 813→1888` 只证明**包围盒变宽了**，
不证明**内容铺开了**。实际情况是：L0 把包围盒撑宽 → zoom 变小 →
真实内容被缩得更小、挤得更左。

我实测的 66.1% 与云端 72.1% 有差距（窗口尺寸不同：我 1600×1000，云端 1600×900），
但**这个指标本身有误导性**——它只量"最左到最右的跨度"，不量内容分布。
用像素网格看，右侧 2/3 是空的，用户观感必然是"画布还是空的"。

截图佐证（v0.12.0，清偏好默认态）：主画布仍几乎全黑，小地图显示拓扑是细长竖条。

### 2.4 建议修复方向（按优先级）

**方案 1（推荐）：统一布局坐标系**

在把节点交给 Cytoscape 布局之前，先对**所有图层**的节点做一次统一归一化：
把每个图层的节点坐标映射到同一包围盒内（等比缩放 + 居中），再跑布局。
这样任何图层的尺度都不会单独主导视图。

**方案 2：L0 改为"背景装饰层"**

L0（人井/电杆/局站锚点）本身不是拓扑结构，不该参与 fit 包围盒。
在 `fullGraphBoundingBox()` 中**排除 L0**（只聚合 body + L3/L4/L5/L6），
fit 只对结构层计算；L0 作为地理参考点可以显示，但不影响视图尺度。

**方案 3（最小改动）：按"结构层"而非"全图"计算 fit**

```ts
// 只聚合承载拓扑结构的图层（body/L3/L4/L5/L6），排除 L0 锚点
const STRUCTURAL = new Set(['body', 'L3', 'L4', 'L5', 'L6']);
```

**并建议把验收指标改掉**：不要只看 `spanX/视口宽`，
应改为**像素分布均匀度**（例如 8×8 网格中含内容且占比 ≥ 1% 的格子数 ≥ 60%），
否则"一根线横贯画布"也能拿到 100% 利用率。

CDP 测量脚本（可在浏览器 DevTools Console 直接粘贴）：

```js
// 各图层布局坐标跨度
let c = null;
for (const d of document.querySelectorAll('div')) {
  if (Object.keys(d).some(k => k === '_cyreg')) { c = d; break; }
}
const cy = c._cyreg.cy;
const g = {};
cy.nodes().forEach(n => {
  const L = n.data('layer') || 'body';
  const p = n.position();
  g[L] = g[L] || { n: 0, x1: 1e9, x2: -1e9 };
  g[L].n++;
  if (p.x < g[L].x1) g[L].x1 = p.x;
  if (p.x > g[L].x2) g[L].x2 = p.x;
});
for (const k in g) console.log(k, g[k].n, '宽度', Math.round(g[k].x2 - g[k].x1));
```

```

L0   21  宽度 1902   ← 21 个节点撑开全图宽度
L5   16  宽度 600
```
