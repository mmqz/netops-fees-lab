## 3. 实测数字（linux/amd64 2 核沙箱，Go 1.27.2，modernc v1.60.1，WAL）

| 指标 | 1 万序列×90 天 | 4 万序列×90 天 | 满配外推（200 万序列，7.3 亿点） |
| --- | --- | --- | --- |
| 每日批量 upsert | P50 242 / P95 265ms | P50 1318 / P95 1504ms | 20 万行/日 ≈ **7.5s（<30s 目标，4× 余量）**；200 万行/日 ≈ 75s（超，触发条件登记） |
| Q1 单序列趋势 | <1ms | <1ms | <1ms（聚簇 seek，规模无关） |
| Q2a 全扫形态 | 3993ms | 17925ms | 90 天窗 ≈ **15 分钟——超阈 180×，禁用于巡检** |
| Q2b 序列驱动 seek | 37ms | 159ms | 200 万序列 ≈ 8s（**快 113×**；实际巡检按指标/局站子集远低） |
| Q3 最新值 | <1ms | <1ms | <1ms（#95 单 seek） |
| DB 体积 | 236MB（262 B/行） | 944MB（262 B/行） | **≈191 GB**；90 天保留口径 47 GB |
| 保留删除（30 天切片） | 5572ms | 25587ms | ≈7µs/行；日删 200 万行 ≈14s；**文件不缩小（freelist），VACUUM 才缩** |

**体积注记**：262 B/行 ≫ 行本体（~70B）——两条 ts 索引把行近似复制两次（40 字符 UUID 序列 id 是主要载体）。体积第一杠杆是**序列 id 短形态**（估计 -40%），不是聚合表。

## 4. 决策（数据依据版）

1. **保留策略 = 显式运维命令，不做自动删除**——指标点是告警证据链一环，自动删除违背「快照不可变、证据可回读」教义；删除须像批次回滚一样是人类的显式决定（`metrics prune --before` 形态，--dry-run + 行数回执，独立 issue 跟踪）；
2. **日聚合表暂缓**——Q1/Q3 规模无关、Q2b 已达序列复杂度，无跨序列年度消费面；建无人查询的聚合表是投机设计。**触发条件**（任一满足立项）：① 真实跨序列长期分析需求；② Q2b 真实巡检范围实测 >5s；③ 单库 >100GB；
3. **摄入**：验收口径通过（4× 余量）；满配口径超标的触发条件登记（并行分片 / 加大 insertChunk）。

## 5. 顺带发现

1. **设计文档 §5.5 Q2 潜伏缺陷**：`(MAX(value) - MIN(value)) < -1.0` 恒不成立（MAX ≥ MIN），谓词**永不触发**——文档印出的 SQL 是死查询。修正为首末差分双形态（全扫 Q2a 仅诊断用 + seek Q2b 巡检用）；
2. **窗口函数语义注记**：窗口在分组**之后**求值——与 `COUNT(*)` 混在同一 SELECT 会让 first/last 静默退化为分组后单行（探针首版实测踩中，§5.5 注记留档防重踩）；
3. 全仓生产代码零 SQLite 窗口函数使用（DuckDB 面才用）——与 2 相互印证。
