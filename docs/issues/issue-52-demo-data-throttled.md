# [P1] 演示数据被人为限流：DEVICE_SITE_NAMES 硬编码 15 个站点，68/83 局站无设备

来源：用户 2026-10-15 现场质疑

用户原话：

> **「我之前不是说了让他按照互联网能找到的公开数据尽量填充完全，没有的模拟，
>  为什么数据这么少？」**

**用户的质疑成立。这不是「没填充」，而是生成器被人为限流。**

---

## 一、根因：硬编码的 15 个站点

`scripts/realdata/workbooks.py`：

```python
DEVICE_SITE_NAMES = [
    "哈尔滨市", "大庆市", "齐齐哈尔市", "讷河市", "嫩江市", "加格达奇区", "塔河县", "漠河市",
    "牡丹江市", "佳木斯市", "尚志市", "绥化市", "伊春市", "七台河市", "鸡西市",
]   # ← 只有 15 个

for i, s in enumerate(dev_sites):      # 15 个
    for j in (1, 2):                   # 每站 2 台
        devices.append(...)            # → 共 30 台
```

**而 `sites` 有 83 个**（全部 OSM 真实局站，数据源是齐的）。
**即：68 个真实局站被生成器忽略，从未分配设备。**

## 二、连锁反应：几乎所有类型都被这个基数压住

30 台设备是**一切的下游上游**：

```
15 站点
  └─ 30 设备          ← 硬编码限制在此
       ├─ 90 端口      （每设备 3 个）
       ├─ 60 板卡      （每设备 2 个）
       ├─ 15 机架      （每设备局站 1 个）
       ├─ 15 ODF       （每设备局站 1 架）
       │    └─ 120 ODF端子（每架 8 个）
       ├─ 10 机房有设备（83 个机房中）
       └─ 32 电路      （设备间）
```

**所以「数据少」不是某一类的问题，是基数被锁死在 15 个站点。**

## 三、实测：与真实规模的差距

| 项 | 真实应有 | 当前 | 差距 |
| --- | --- | --- | --- |
| 局站 | 83（**真实数据，已齐全**） | 83 | ✅ |
| **设备** | **≥ 83**（每站至少 1 台） | **30** | **缺 64%** |
| 端口 | ≥ 250（每设备 3 个） | 90 | 缺 64% |
| 板卡 | ≥ 166（每设备 2 个） | 60 | 缺 64% |
| ODF 端子 | ≥ 664（每架 8 个） | 120 | 缺 82% |
| 电路 | 数百（地市间网状） | 32 | 差一个数量级 |

### 真实世界对照

```
黑龙江省：13 个地市 + 67 个县市 ≈ 80 个传输节点
真实省干网：每个局站都有传输设备（SDH/OTN/PTN），且多为 1+1 主备
→ 83 个局站应有 80+ 台设备（含主备可达 160 台）
当前：30 台  ← 只有真实规模的 1/3 ~ 1/5
```

## 四、与用户原始指令的偏离

用户指令（v0.8.0 立项时）：

> **「数据用互联网公开数据填充，完全找不到的用模拟数据」**

**OSM 提供的 83 个局站是公开数据，已经拿到了**——
但没有据此推导出应有的设备规模，而是硬编码了 15 个地名。

这**违背了「尽量填充完全」的指令**：公开数据的价值没有被用尽。

## 五、影响

| 影响面 | 说明 |
| --- | --- |
| **演示观感** | 83 个局站的省干网只有 30 台设备，一眼看出规模不足 |
| **拓扑密度** | 68 个局站在地图上有位置但无设备（空点） |
| **#51 的前置** | 即使扩展物化覆盖，基数仍只有 30 台 |
| **AI 分析样本** | 电路仅 32 条，影响的业务分析样本太少 |

## 六、修复方向

### 6.1 解除站点限制（核心）

```python
# 改为：所有 OSM 局站都参与（或至少覆盖地市 + 主要县市）
dev_sites = sites            # 83 个全用
# 或按层级：地市 2 台（主备）/ 县级 1 台
```

**预期规模**：

```
83 站点 × 平均 1.5 台 ≈ 125 台设备（较当前 +317%）
→ 端口 ~375，板卡 ~250，ODF端子 ~664，机架 ~83
→ 总资源量 1,991 → 约 4,000+
```

### 6.2 按层级差异化（更真实）

```
地市（13 个）   → 每站 2-4 台（核心/汇聚，主备）
县级（≈70 个）  → 每站 1-2 台
接入点          → 视需要
```

### 6.3 同步扩展电路

设备从 30 → 125 后，电路应从 32 → **数百条**（地市间网状 + 县到地市汇聚）。
这才能支撑「影响分析」有足够样本。

### 6.4 与 #51 / #50 的协同

```
本 issue  解除生成限流  → 数据变多
#51       扩展物化覆盖  → 更多类型进工作台
#50       规模保护      → 确保变多后画布不卡
```

**三者必须一起规划**：只解除限流会让画布更卡；只做规模保护则数据仍少。

## 七、验收

- [ ] 局站→设备覆盖率 **≥ 80%**（当前 18%：15/83）
- [ ] 设备总数 ≥ 100（当前 30）
- [ ] 端口 / 板卡 / ODF端子 按设备比例同步扩展
- [ ] 电路数 ≥ 200（当前 32），支撑网状影响分析
- [ ] 地图上无「有局站无设备」的空点（或有合理说明）
- [ ] 数据规模增长后，画布与地图性能仍满足 #50 基线
- [ ] `manifest.json` 如实披露各类型规模与真实性边界
