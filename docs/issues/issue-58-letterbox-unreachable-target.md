## 二、遗留问题：护栏在纵向约束占主导时静默失效

### 2.1 实测

修复后默认态：

```
zoom = 0.522
结构包围盒 bb.w = 869, bb.h = 1081   → 宽高比 0.804（高瘦）
视口 1318 × 624                      → 宽高比 2.112
8×8 网格：仅 20/64 格有内容，第 6-7 列全 0
横向利用率 = 34.1%
```

**比修复前的 66.1% 还低**——因为修复前是「L0 撑宽 + 内容挤左」，
现在是「整体缩小 + 右侧留白」，两种不同的不理想。

### 2.2 手算复现（用实际数据跑 fitToView 公式）

```js
vw=1318, vh=624, bb={w:869, h:1081}
FIT_PADDING=40, FIT_PAD_V_MIN=12, FIT_UTILIZATION_TARGET=0.72

条件 bb.w/bb.h(0.804) < vw/vh(2.112) → true（进入护栏分支）

zoomNeeded = 0.72 × 1318 / 869 = 1.092
padNeeded  = (624 - 1.092 × 1081) / 2 = -278.2   ← 负数！

Math.max(12, -278.2) = 12                         ← 负数被静默钳掉
最终 padY = 12

padded = {w: 869+80 = 949, h: 1081+24 = 1105}
zoomX = 1318/949 = 1.3888
zoomY = 624/1105 = 0.5647
实际 zoom = min(1.3888, 0.5647) = 0.5647          ← 纵向约束主导
横向利用率 = 0.5647 × 869 / 1318 = 37.2%          （实测 34.1%，含边距误差）
```

### 2.3 设计缺陷

```ts
// TopologyCanvas.tsx:858-865
if (bb.w / bb.h < vw / vh) {
  const zoomNeeded = (FIT_UTILIZATION_TARGET * vw) / bb.w;
  const padNeeded = (vh - zoomNeeded * bb.h) / 2;
  if (padNeeded < padY) padY = Math.min(FIT_PADDING, Math.max(FIT_PAD_V_MIN, padNeeded));
}
```

**当 `padNeeded < 0` 时，说明"横向 72% 所需的 zoom 会让内容高度超出画布"——
目标物理不可达。但代码只是把负数钳到 12，不报错、不降级、不改目标。**

结果：护栏看起来"生效了"（padY 从 40 变成 12），实际只是退化成普通 fit。

数学判据：**护栏能达成 72% 的前提是 `bb.h / bb.w < (vh/vw) / 0.72`**，
即内容不能比 `2.112/0.72 = 2.93:1` 更"高瘦"。当前 1081/869 = 1.24（竖直方向），
换算后明显超限。

### 2.4 为什么 P2 而非 P1

- 拓扑结构完整、可交互、不丢数据；
- 用户可手动缩放（滚轮）或按 F；
- 相比 #54 原本的「尺度失衡」（L0 主导视图），这是程度更轻的观感问题。

## 三、建议修复

### 方案 A（推荐）：区分"可达/不可达"两种路径

```ts
if (bb.w / bb.h < vw / vh) {
  const zoomNeeded = (FIT_UTILIZATION_TARGET * vw) / bb.w;
  const padNeeded = (vh - zoomNeeded * bb.h) / 2;
  if (padNeeded >= FIT_PAD_V_MIN) {
    // 可达：正常收窄纵向留白，达成横向目标
    padY = Math.min(FIT_PADDING, padNeeded);
  } else {
    // 不可达：纵向约束主导 → 显式声明，横向利用率目标放弃
    padY = FIT_PAD_V_MIN;
    // 可选：记录 zoomMode = 'vertical-bound' 供调试/埋点
  }
}
```

关键差别：**让"无法达成"成为显式分支，而不是依赖 `Math.max` 吞掉负数。**

### 方案 B：按内容宽高比选择主约束

内容"高瘦"时，横向铺开本来就该放弃——此时更该关注**纵向是否充分利用**。
建议验收指标也按内容形态分类：

| 内容宽高比 | 主指标 |
| --- | --- |
| > 1.5（宽扁） | 横向利用率 ≥ 70% |
| 0.8 – 1.5（接近方） | 两向利用率均 ≥ 55% |
| < 0.8（高瘦） | **纵向利用率 ≥ 70%**（当前 0.5647×1081/624 = 97.8%，其实很好）|

**注意：按这个分类，当前高瘦内容的纵向利用率其实是 97.8%——视觉问题主要在"
右侧大片空白"的观感，而非内容真的没铺开。**

### 方案 C：补充"高瘦内容"的呈现策略

若结构本身是竖长的（本例 869×1081），可考虑：
- 画布区域改为竖长比例（脱离固定 1316×624）；
- 或布局算法倾向横向展开（如 `grid` 的列数按视口宽高比计算）。

## 四、验收标准（修订）

1. `padNeeded < 0` 时有显式分支，不再依赖 `Math.max` 静默吞负数（可用日志/埋点断言）；
2. 验收指标按内容宽高比分类，不再对"高瘦内容"套用 72% 横向目标；
3. 明确"无法达成目标"时的行为文档化（是放弃横向、还是改布局）；
4. 补前端单测：构造 `bb={w:869,h:1081}` + 视口 `1318×624`，
   断言 padY 取值路径为"不可达分支"而非静默钳制。
