# [P1] 拓扑连线跨越数百公里：画布画的是「业务电路端到端」，不是「网络逐跳」

来源：用户 2026-10-15 现场反馈（v0.11.0 实际使用）

用户原话：

> **「各个设备的链接都是按照链路走的啊，逻辑链路在物理之上，现在有不少的点间隔非常远直接连上了，
>  现在的网络一团，真实的网络不可能是这样的」**

**用户的判断完全正确，且经数据完全证实。**

---

## 一、实测：连线的距离分布

对 32 条连线逐条计算 A/Z 端设备的球面距离：

```
最短      112 km
最长      935 km
均值      448 km
> 200km  31 / 32 条   ← 96.9%
```

样例：

```
CIR-007   DEV-962010355-01  ←─ 935 km ─→  DEV-4059698545-01
CIR-008   DEV-280162986-01  ←─ 885 km ─→  DEV-304758391-01
CIR-022   DEV-962010355-01  ←─ 862 km ─→  DEV-244081526-01
…
CIR-009   DEV-4059698545-01 ←─ 112 km ─→  DEV-6359892789-01   ← 最短
```

**没有一条是真实网络设备互联该有的形态**——真实设备直连通常几公里内
（同局站内）、同城几十公里（城域环）、省干数百公里但那**不是设备直连**，
而是经光缆段 + 波道逐段承载。

## 二、根因：materialize 只实现了一条规则

`internal/sim/materialize.go:182-233`：

```go
// Links: circuits in ascending natural_key order; the a_end/z_end
// relations must both resolve to workspace devices; …
circuitResources, _, err := tx.Resources.Search(ctx, repo.ResourceSearchFilter{
    Type: domain.ResourceTypeCircuit,          // ← 只取 circuit
})
for _, res := range circuitResources {
    aEnd, zEnd, ok, err := circuitEndpoints(ctx, tx, res.ID)
    …
    // devA ↔ devZ 建一条 link
}
```

**即：一条电路 = 一条连线，直接连 A 端设备与 Z 端设备。**

## 三、为什么这是层次错误

```
真实网络分层                     当前画布
─────────────                    ──────────
L6 业务   客户专线（哈 → 齐）
              ↓
L3 电路   CIR-001（哈设备 ↔ 齐设备）   ← 画布画的就是【这一层】
              ↓ 承载                    （所以跨 270km）
L3 波道   OCH-HDQ-01（逐段）
              ↓ 路由
L2 光缆   哈-大段 / 大-齐段（各 ~150km）
              ↓ 成端
L1 设备   相邻站点设备互联             ← 拓扑图【本应画这一层】
```

**电路是「端到端业务」，不是「物理连接」。**
把电路的 A/Z 两端直接连线，等价于在拓扑图上画「哈尔滨到齐齐哈尔有一条线」——
跳过了中间所有真实节点，视觉上就是一团远距离飞线。

## 四、中间层数据已经存在，只是没被使用

```
资源：otn_och 14 / cable_segment 23 / optical_cable 7 / fiber 56
关系：carried_by 32 / routed_over 14 / uses_fiber 14 /
      segment_of 23 / cable_a_end 7 / cable_z_end 7 / connects_device 7
```

**即：数据模型（v0.7 扩容）已经把 L2/L3 层建好了，
但 materialize 停留在 v0.5 的「device + circuit」两类型时代，从未跟进。**

这与 issue #24（lab 与扩容模型的关系）同源——当时裁决「lab 保持现状」，
但那个裁决**低估了后果**：不是「少了几个新类型」，而是「拓扑图的物理意义错了」。

## 五、影响

| 影响面 | 说明 |
| --- | --- |
| **拓扑图不可信** | 演示/评审时一眼看出不是真实网络 |
| **影响分析失真** | 图上「相邻」的两设备可能相距 900km |
| **课程/宣传受阻** | 这是产品最直观的门面 |
| 与用户目标冲突 | 用户目标是「真实网络运维」，不是示意图 |

## 六、修复方向

### 方案 A：物化**物理层**连线（推荐）

按光缆段的 A/Z 端站点定位设备，建立**相邻设备**连线：

```
cable_segment（哈-大段）
    ├─ a_end_box → 站点 → 该站点设备
    └─ z_end_box → 站点 → 该站点设备
    ⇒ link: 哈设备 ↔ 大设备（~150km，省干尺度，可接受）
```

**但 150km 仍偏长**——因为光缆段本身是「哈-大」整段。若要更真实，需
把光缆段按**接头盒（splice_box 46 个）**细分，或直接按 `fiber` 的成端关系建链。

### 方案 B：物化**波道**层次的逐段路径

`otn_och.routed_over` 给出波道经过的光缆；把路径拆成**相邻站点跳**：

```
OCH-HDQ-01 routed_over [OC-HDQ]
   光缆锚点链：哈 → 大 → 齐
   ⇒ 两条 link：哈↔大、大↔齐            ← 这才是真实的网络拓扑
```

**推荐 B**：`optical_cables` 表已有 `a_end_site`/`z_end_site` 与锚点链里程，
且 v0.8.0 的生成器已算出**锚点链**（哈大齐 7 条走廊），天然支持分段。

### 方案 C：画布分层显示（补充，非替代）

即使连线修好，也应支持**按层切换**：

```
视图切换：[物理层] [传输层] [业务层]
  物理层：设备 + 光缆段（真实跳）
  业务层：客户 + 电路（端到端，允许飞线，因为那本就是逻辑关系）
```

**注意**：逻辑层画飞线是**正确的**（逻辑链路本就跨物理），
问题在于**当前把逻辑层当成了唯一的拓扑视图**。
