# 2D/3D 相机锁联 + 初始视野比例不合适（用户反馈）

## 环境
- 来源：用户现场反馈（2026-10-12，v0.6.2 验收后）：「2D 图锁在一起了，默认没有按照合适的比例缩放」
- 版本：v0.6.2 @ 769ad37（用户实际运行 v0.3.0，见 issue-14）
- 视图：工作台 → 2D 地图 / 3D 地图切换

## 现象
1. 在 2D 视图平移/缩放后切到 3D，3D 完全继承 2D 的 center/zoom（仅 ±1.3
   zoom 补偿近似对齐）；在 3D 平移后切回 2D 同样被带着走——两个视图
   「锁在一起」，无法各自保持视角。
2. 初始视野比例：2D fitBounds `maxZoom=9` 把城市尺度数据压远（同城设备
   屏幕间距 <56px 全并入一个聚簇）；固定 80px 留白在分栏/半屏小画布上
   占短边 ~1/3，内容显小。

## 根因
- 结构性设计取舍：GeoCanvas 单实例承载两视图（省一个 WebGL 上下文与
  瓦片缓存），相机状态从未分视图保存——视野对齐靠 ±1.3 补偿 hack。
- 比例参数面向全省跨度标定（演示数据跨 7° 纬度），未照顾城市尺度与小画布。

## 修复（v0.6.3）
- 每视图独立相机快照：离开视图存 center/zoom/bearing/pitch，进入时恢复；
  首次进入按该视图 fitBounds；经拓扑图中转 = 重挂载重新适配（可预期）。
  ±1.3 补偿 hack 移除；2D 自定义 bearing 不再被切回时归零。
- 2D maxZoom 9→12.5；留白改容器短边 8% 自适应（夹 [24,80]px）；3D 上限
  7.2→8.6；聚簇展开 maxZoom 升级为 max(当前+2.2, 成员 bbox cameraForBounds
  解)——哈尔滨 3 台一次点击从 z4.8 拆到 z11.5（旧版需两次）。
- 回归：`scripts/w17_browser_regression.sh` G1/G2（相机恢复含自定义
  bearing）、B1（一次点击拆簇）。
- 设计决策：[ADR-0012](../adr/0012-map-camera-independence-and-elevation.md) D1。
