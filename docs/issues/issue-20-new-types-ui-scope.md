# [设计决策] 新增 30+ 资源类型的 UI 支持范围

关联：`docs/design/data-model-v1.md` §3.2（45 类资源）

## 问题

设计新增 37 类资源（光缆/纤芯/波道/客户/业务/OLT…）。
**这些类型是否都需要界面支持？**

## 候选方案

**方案 A：只做数据层（默认）**
- schema + 导入 + API 全支持；UI 只复用现有「资源浏览」页的通用表格
- 优点：工作量小，不阻塞数据底座；缺点：光缆等专用视图缺失

**方案 B：全部做专用 UI**
- 每类资源都有定制页面/画布视图
- 优点：用户体验完整；缺点：工作量极大，且多数类型当前无数据

**方案 C：按优先级分批**
- P0 类型（光缆/纤芯/业务）做 UI；P1/P2 先只做数据层

## 评判标准

本项**难以量化测试**（属产品取舍），评判依据：

1. **现有 UI 的复用能力**：`Resources.tsx` 的通用表格能否直接展示新类型
   （若能 → 方案 A 已够用）
2. **参赛/演示需求**：哪些类型的可视化对评审有说服力
3. **数据可用性**：当前无真实数据的类型，做 UI 是否属于无效投入

**建议先验证第 1 条**——若通用表格已能展示新类型，方案 A 成立。

## 默认方案（不能决定时采用）

**方案 A（只做数据层）**，理由：
- 用户目标明确是「数据底座 + AI 分析」，界面是次要目标（§7.1）
- 多数新类型当前无数据（占位数据阶段）
- 通用资源页可覆盖基本查看需求

代码中标记：
```tsx
{/* TODO(design-v2): 新资源类型的专用 UI 见 issue #20；
    当前全部复用通用资源表格。 */}
```

## 处置指令（给实施方）

**这不是「等人类裁决」的阻塞项，而是「你测试后择优」的决策项。**

1. **先做实验**：按下方「候选方案」各实现一个最小版本（可只在测试内验证，不必进主干）
2. **用数据选**：按「评判标准」量化对比，选胜出者
3. **不能决定时**：采用「默认方案」，并在代码中留 `TODO(design-v2): ...` 标记 +
   在本 issue 回帖记录「为何未能决定」，供后续替换
4. **无论选哪个**：把结论回写 `docs/design/data-model-v1.md` 对应小节（含决策理由）

> 原则：**可测的就测，不可测的用默认值并显式标记**——
> 不要让任何一项悬空导致实施卡住。
