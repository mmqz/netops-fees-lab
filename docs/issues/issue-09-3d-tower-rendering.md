# 3D 视图节点渲染为巨型光柱 + 底图为平面投影（非真实地形）

## 环境
- 平台：**所有平台**（Linux/Docker 实测，与 MIME/CSS 缺陷无关）
- 版本：v0.6.0 @ 2033de8
- 视图：工作台 →「3D 地图」
- 前置：需先修复 issue-01（否则地图黑屏，本问题不可见）

## 现象（两点）

### A. 节点呈巨型光柱，粗细随缩放变化、高度无上限
3D 视图中每个设备被渲染成一根蓝色柱体：
- **粗细不恒定**：缩小地图时急剧变粗，最大可达 217px（设计目标 7px）
- **高度无上限**：以「真实米」计可达 62 公里，远超任何物理实体
- 柱子冲出画布顶部被裁切，相互遮挡并覆盖底图

### B. 3D 底图是平面投影，不是真实地形
「3D 地图」实际为**平面栅格底图 + 倾斜相机**，没有高程数据：
```
basemap:      type = "raster"   ← 平面瓦片贴图
basemap-ref:  type = "raster"
terrain:      null              ← 无地形（无 DEM/terrain source）
maxPitch:     60°
```
即所谓 3D 只是把 2D 地图转了个 58° 角度，**山体、海拔、地形起伏均不存在**。

## 实测数据

### 缩放时的尺寸变化（真实滚轮交互）

| zoom | 节点底面宽 | 屏幕高 | 实际高度（米） |
| --- | --- | --- | --- |
| 8.41 | 19–42 px | 26–52 px | 15,383 |
| 7.20 | 25–40 px | 26–52 px | 35,502 |
| 6.40 | **109–217 px** | 23–49 px | **62,001** |

观察：
- **宽度随缩放剧烈变化**（6.4 时 217px vs 8.41 时 19px，相差 11 倍），与注释「恒定 7px 宽」严重不符
- **实际高度随缩小而暴涨**（6.4→62km，7.2→35.5km），物理上不可解释
- 屏幕高度基本恒定（~52px）——这是设计的「恒定可见」策略，代价是真实高度失真

### 单点几何（zoom 7.2）
```
设计目标底面宽:       7 px      (GeoCanvas.tsx:93 TOWER_FOOTPRINT_PX)
按代码公式计算:      24.5 px
按地图真实分辨率:     14 px
实测屏幕宽度:        39.9 px
towerPx:             58        (= 18 + 连接数 × 10)
实际高度:            35,502 m
宽高比:              1 : 1.31  （设计意图 1 : 7.4）
```

## 根因分析

### 根因 1：底面宽度未恒定（TOWER_FOOTPRINT_PX 语义 + mpp 公式偏差）
`web/src/components/lab/GeoCanvas.tsx:332-335`
```js
const mpp = metersPerPixel(lat, zoom);
const halfLat = (TOWER_FOOTPRINT_PX * mpp) / 111320;
const halfLng = (TOWER_FOOTPRINT_PX * mpp) / (111320 * cosLat);
```
1. 常量名为 FOOTPRINT（底面宽度语义），却赋给 halfLng/halfLat（半宽），
   实际底面宽 = 2 × 7 = 14px
2. `metersPerPixel` 公式偏高约 1.75 倍：
```
代码公式:  156543.03392 × cos(lat) / 2^zoom  = 675.04 m/px
地图实测:  111320 × cos(lat) / pxPerDegLng   = 386.16 m/px
比值:      1.748
```
两者叠加：`7 × 2 × 1.75 ≈ 24.5px`，再经 58° 斜视水平拉伸达 ~40px。
缩放变化时 `mpp` 随 2^-zoom 变化，而重建时机/精度导致实测宽度进一步漂移（最大 217px）。

### 根因 2：高度基准无物理约束
`web/src/components/lab/GeoCanvas.tsx:431-439`
```js
'fill-extrusion-height': ['interpolate', ['exponential', 2], ['zoom'],
  0,  ['*', ['get', 'towerPx'], 90000],
  16, ['*', ['get', 'towerPx'], 90000 / 65536]]
```
高度按 `towerPx × 90000 × 2^-zoom` 计算，目的是让屏幕高度恒定（~52px）。
该策略使**真实高度**在低缩放下达到数十公里，且无上限钳制；
柱体被画布裁切，高度信息反而不可读。

### 根因 3：3D 无地形数据
样式仅注册两个 `raster` source（ESRI World_Dark_Gray_Base / _Reference），
未注册任何 terrain source，`map.getTerrain()` 返回 `null`。
因此「3D」仅为相机倾斜，不含地形起伏。

## 影响
- 3D 视图**不可用于观察设备地理分布**（节点相互遮挡、覆盖底图、顶部裁切）
- 缩放到较大范围时柱体变成巨型方块，完全失真
- 「3D」名不副实：无地形，仅平面倾斜
- 与 2D 视图观感割裂

## 建议修复方向（讨论用）

针对根因 1：
- 明确 `TOWER_FOOTPRINT_PX` 语义（直径则除以 2，半径则重命名）
- 校正 `metersPerPixel`，或改用 `map.project()` 反推真实分辨率
- 确保 footprint 在缩放时真正恒定（增加断言/快照测试）

针对根因 2：
- 为高度设置物理上限（如按设备类型给定合理米数，或屏幕像素上限）
- 或将高度改为**对数/归一化**映射，避免真实高度失真到数十公里
- 避免柱体溢出画布被裁切

针对根因 3：
- 若需真实地形：注册 terrain source（如公开 DEM 瓦片）并 `map.setTerrain()`
- 若仅需视觉纵深：在文档/UI 中明确说明「3D = 倾斜相机」而非真实地形，避免误解

## 验收标准
- [ ] 节点底面宽度在缩放时保持恒定（误差 ≤ 2px）
- [ ] 真实高度有合理上限，不出现数十公里
- [ ] 节点不遮挡底图主要区域，柱体不被画布裁切
- [ ] 3D 视图的定位（真实地形 or 倾斜相机）在 UI/文档中明确
- [ ] 2D/3D 切换无回归
- [ ] 现有前端测试全绿
