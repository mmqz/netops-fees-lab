# #118 费用×指标交叉验证的对称空白：八场景缺「有量无费」（missing-billing）

> **状态**：已修复（2026-10-23，v0.15.2 后 main）。GitHub issue：https://github.com/mmqz/netops-lab/issues/118

## 1. 发现背景

#114 落地第七场景 `idle-billing`（有费无量）时，交叉验证补上了「费用面说在计费、指标面说零采集」的方向。全仓调研（fees-layer 现状梳理第二轮）发现**对称方向零覆盖**：一个站点可以同时满足"指标面关联资源该账期有采集点"与"费用面该账期无任何该类型计费记录"——**业务量在跑、账单没有来**，这是直接资损形态（漏收嫌疑），而八场景没有一个能发现这种反向矛盾。docs 全局 grep「漏收/missing-billing」零命中。

## 2. 根因

- #114 的组合方向是**费用面驱动**（引擎 `SitePeriodTotals` 的行是遍历宇宙），天然只能发现"有账单"侧的异常；无账单的站点根本不进宇宙；
- 「有量无费」的异常主体是**资源**（有业务量的那个），宇宙必须从 confirmed 关联侧出发反查费用面——组合方向与既有七场景相反，#64/#114 两轮都没有走到。

## 3. 修复方案：第八场景 `missing-billing`（有量无费）

### 3.1 判定口径

**已确认关联的在网/在建资源在该账期窗口内有指标采集点，而费用侧同账期无该类型计费记录。**

- 跨层组合（#58 架构裁决：Go 内组合，禁跨引擎 ATTACH），方向与场景 7 相反：
  1. 引擎 `SitePeriodTotals`（费用面，Parquet）**一次调用**取有费用的 (站址, 账期) 集，内存 set 反查——无账单的组合不产生引擎往返；
  2. `FeeSiteLinks.List(status=confirmed)` 取关联宇宙（人类裁决过的配对才可测量；pending 未裁决、dismissed 已否决，均不进）；
  3. 退休状态资源排除（默认 `停用,退网`，沿用场景 1 的 `status` 参数口径）：**不给退休资源计费是正确形态**（场景 1 管反向），计入只会制造噪音；
  4. 按 (资源, 账期) memoize `CountPointsOfResource` 点数（#85/#114 双 memo 纪律：资源一站一查、计数一 (资源, 账期) 一查）；
  5. **窗口内点数 > 0 且 (站址, 账期) ∉ 有账集合 → 触发**。
- month=0（整年口径）逐月开窗（1..12 各自的 [1日, 末日] RFC3339 字典序窗口），线索携带具体月份；month=m 单月。
- **无阈值**：点数>0 是确定性信号（与场景 7 的零点信号对称）；metric = 窗口内指标点数（`metricPoints`），线索按点数降序。
- **零行证据形态**：`evidenceTotal` 恒 0、锚点列表恒空（非 null，#93 纪律）——费用侧零行**即异常本体**，锚点指向不存在的行才是撒谎；快照层仍是无账可查时的回读源。

### 3.2 诚实注意义务（写进契约的一部分）

线索 note 恒携带告诫：**账期无记录 ≠ 漏收认定**——季度/年度结算（账期粒度不在本月）、该费用类型尚未导入（四类型分文件）、结算主体挂账在其他编码，在该证据形态下全部同相。线索仅供人工核实。无 confirmed 关联的编码不在本场景测量（`unlinked` 的业务）；退休资源不在（`retired-billing` 管反向）。

## 4. 消费面闭集同步（八处，#114 先例清单）

## 5. 验证

- 组合单测 `TestRisksMissingBillingComposition`：触发（UNBILLED-1 五月 2 点）/ 已账静默（BILLED-1）/ 退休排除（停用资源有点无账也不触发）/ 无点静默 / 整年逐月（五月+六月双线索、点数降序）/ 零行证据形态（threshold nil、evidenceTotal 0、空锚点非 null）。
- 「资源消失但关联在」形态**不可构造**：`fee_site_links.resource_id` 带真实 FK 且级联删除——`ErrNotFound` 分支为防御性对称（与场景 7 同理由保留），测试注释如实声明。
- duckdb 真引擎 e2e：UNBILLED-SITE 六月 1 点无账 → 恰一线索；ACTIVE-SITE（有点有账）与 RETIRED-SITE（退休）静默；单月诚实空；确定性重跑循环收录场景 8。
- 门禁：默认 + duckdb 双构建全绿、gofmt 空、vet 0（双构建）、tsc 0、vitest 188/188。
