# [P3] 拓扑工作台布局：头部冗余行 + 面板默认展开挤占画布

来源：用户 2026-10-13 现场反馈（v0.8.0 真实数据演示）

用户原话（拆为 4 条诉求）：

> 1. **「`158ae2f68bcd…—设备 30↑30 接口 20↑20 链路 10↑10` 这一行移到『拓扑工作台』这一行」**
> 2. **「运行校验 / 执行操作 / 撤销最近变更 / 创建检查点 / 前后对比 / 导出报告 / 折叠面板
>    这些按钮和下一行的画图按钮放一行」**
> 3. **「面板默认折叠，点击设备或者点击打开」**
> 4. **「这样能给画布更大的展示空间，画布下面还有能使用的空间」**

## 一、现状结构（代码核对）

`web/src/pages/LabWorkspace.tsx` 头部目前是**三行**：

```
第 1 行：工作台名 + hash chip + 评分 chip + 设备/接口/链路 三个 CountChip
         （L636-652，.lab-head-meta）
第 2 行：7 个动作按钮（L654-684，.lab-head-actions）
         └ 运行校验 / 执行操作 / 撤销最近变更 / 创建检查点 / 前后对比 /
           导出报告 / 折叠面板
第 3 行：画布工具栏（视图/布局/模式/工具等图标按钮）
         （.lab-canvas-toolbar，在画布卡片内）
```

对应 CSS：`.lab-pagehead` padding 8px 12px + margin-bottom 8px（global.css:3124）、
`.lab-head-meta` flex-wrap（global.css:3129）。

**问题**：垂直方向吃掉约 **100px+**，而画布是主要工作区。

## 二、面板默认展开（诉求 3）

`LabWorkspace.tsx:167-173`：

```tsx
function readPanelCollapsed(workspaceId: string): boolean {
  try {
    return localStorage.getItem(`netops-lab.panel.${workspaceId}`) === '1';
  } catch { return false; }   // ← 无记录时返回 false = 默认展开
}
```

**默认展开**，且分栏比例 `.lab-split` 为 **68fr : 32fr**（global.css:1898）——
右侧面板长期占掉约 **1/3 画布宽度**。

## 三、诉求逐条

### 诉求 1：计数 chip 移到标题行

把 `设备 30↑30 接口 20↑20 链路 10↑10` 与 `hash/评分` chip 一起并入
**「拓扑工作台」标题所在行**（页头面包屑行），消除第一行的独立占用。

### 诉求 2：7 个动作按钮与画布工具栏合并为一行

把 `.lab-head-actions` 的 7 个按钮**下移到画布工具栏同一行**
（与视图/布局/模式图标按钮同行），消除第二行的独立占用。

### 诉求 3：面板默认折叠

`readPanelCollapsed` 无记录时返回 **true**（默认折叠），
点击设备/链路或点击展开按钮时再打开，且**点击后自动展开**。

### 诉求 4：释放画布空间（含下方空白）

用户明确指出「**画布下面还有能使用的空间**」——
即当前布局在画布下方仍留有未利用的垂直空间，应一并纳入画布高度计算。

## 四、预期收益（估算）

```
现状：页头 3 行 ≈ 100px+  面板占宽 32%
目标：页头 1 行 ≈ 40px    面板默认折叠（宽度 100%）
画布垂直净增 ≈ 60px，水平净增 ≈ 32%（折叠态）
```

## 五、注意事项

- 面板折叠是**持久化偏好**（localStorage per workspace）——默认值改动不应
  覆盖用户已显式设置的偏好（已设置时仍按其值）
- 按钮下移到画布工具栏后，需保证**窄视口下不换行溢出**
  （工具栏已有 `flex-wrap: nowrap` + 提示绝对定位的处理，global.css:2183+）
- 「折叠面板」按钮本身下移后，其语义（折叠/展开）保持不变
