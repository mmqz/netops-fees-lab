# [设计缺失] lab 仿真工作台与扩容后模型的关系未定义

关联：`docs/design/data-model-v1.md` §2（一张图）、§3（45 类资源）

## 问题

项目已有**仿真工作台（lab）**，它从导入资源**物化**出虚拟拓扑，
使用**独立于 `resources` 的另一套表**：

```
virtual_devices / interfaces / links / changesets / check_runs / checkpoints
```

实测当前物化规则（`internal/sim/materialize.go`）：
- 只处理 **`device`** → `virtual_devices`（`statusInNet = "在网"` 映射为 up）
- 只处理 **`circuit`** 的 a_end/z_end → `links`
- **其余 6 类资源完全不参与**

扩容到 45 类资源后，**两者关系未定义**：

1. lab 是否要物化光缆/纤芯/波道/业务？
2. 若物化，`links` 表只有「接口—接口」一种边，**表达不了多层**
3. 若不物化，lab 与 §10 的图查询是**两套并行系统**，AI 该用哪个？
4. 既有 lab 的 5 个 MCP 工具与校验规则（CHK-001~005）是否扩展到新类型？

## 影响

- 实施方会**破坏既有 lab 功能**（或无视新模型）
- AI 面对两套图（`resources/relations` 与 `virtual_devices/links`）会**选错**
- 既有 331+ 测试与仿真校验规则可能失效

## 建议方向

**方案 A：lab 保持现状，明确边界**
- lab 只服务「设备级连通性推演」（现有能力）
- 新模型（多层图）由 `resources/relations` 承载
- 文档明确：**lab = 设备级沙盘；统一图 = 全量资源模型**
- AI 分析用统一图，仿真操作用 lab

**方案 B：lab 扩展到多层**
- `links` 表扩展为通用 `sim_edges(type, ...)`，支持多层
- 工作量大，且要重做 5 个 MCP 工具与校验规则

**方案 C：lab 从统一图投影**
- lab 不再是独立表族，而是统一图的「可写投影」
- 架构最干净，但**推翻既有实现**（v5 以来的仿真表全部重做）

## 评判标准

1. **既有测试**：选任何方案后，现有 lab 测试（`internal/sim`）是否全绿
2. **AI 清晰度**：能否用一句话说明「什么时候用 lab、什么时候用统一图」
3. **迁移成本**：方案 B/C 对 v5 仿真表与 5 个 MCP 工具的影响
4. **能力覆盖**：§10.5 的根因追溯是否需要 lab（若不需要，方案 A 足够）

## 默认方案（不能决定时采用）

**方案 A（lab 保持现状 + 明确边界）**，理由：
- 「不做破坏性变更」（§10.10 原则）
- §10.5 的根因追溯**只需要统一图**，不依赖 lab
- 参赛目标是「数据分析异常」，lab 是可选的推演能力

## 处置指令

本项为**设计缺失**（非「两难选择」）：实施前必须补齐设计，
否则实施方只能靠猜，且猜错会静默致错。

1. **先补设计**：把本 issue 的设计结论回写 `docs/design/data-model-v1.md`
2. **可测的项要测**：给出量化对比（如存储规模、查询耗时、行数）
3. **不能决定时**：采用「默认方案」+ 代码 `TODO(design-v2): ...` 标记 +
   本 issue 回帖记录原因，供后续替换
4. **不要绕过**：本项缺失会导致后续所有分析结论不可信，不允许「先实现再说」
