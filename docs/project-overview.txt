云网运维自动化：项目梗概
================================

涵盖两个项目：NetOps Lab（云网资源治理与 AI 仿真工作台）、PCDN 自动化工具（违规接入检测与封禁处置）。
共同起点：电信运维的大量时间耗在「从若干网页系统里人工抄数据、人工判断、人工到另一个系统操作」。

--------------------------------
一、一句话概括
--------------------------------

NetOps Lab
  把分散在 Excel 台账里的 IPRAN 网络资源，变成可查询、可校验、可仿真、AI 能直接读的
  网络知识库。故障影响面分析与日常巡检，从人工查表变成一次查询。

PCDN 自动化工具
  把「IDC 系统导流量报表 -> 筛异常账号 -> AIOBS 系统批量封禁」这条每天重复的跨系统
  人工流水线，做成可一键 / 定时执行的自动化链路。

两者都在解决同一个母问题：运维工作散落在多个互不相通的后台系统之间，人工搬运数据，
既慢又不可追溯。

--------------------------------
二、解决了什么问题
--------------------------------

[共同的问题结构]

   数据散落            判断靠人脑            操作在另一处
   Excel 台账          经验 / 眼力           后台系统点选
   多个网管系统   -->  逐条比对         --> 手工录入
   报表导出            容易漏、难复现        无留痕

   NetOps Lab 补左侧到中间：把数据变成可推理的模型
   PCDN 工具   补中间到右侧：把判断和操作串成端到端流水线


[NetOps Lab 解决的五个问题]

1. Excel 台账不可信
   几十个 Excel、列名各异、几千行靠肉眼核对。
   做法：列映射确认 + 行级记账 + 确定性校验（同输入同输出、可重算、可回滚）。
   现状：3464 条资源 / 32 类 / 5022 条关系 / 29 种关系类型。

2. 说不清「谁影响谁」
   「这条光缆断了影响多少基站、客户、业务？」纯 Excel 几乎无法回答。
   做法：七层模型（L0 空间 / L1 设备 / L2 光缆 / L3 传输 / L4 接入 / L5 逻辑 / L6 业务）
         + 显式关系图，沿依赖方向追溯，分开输出「受影响」与「候选根因」。
   红线：关系只来自数据显式声明，绝不从名称、前缀、IP 段推断——宁可答不知道。

3. 改动不敢做
   做法：仿真工作台。把资源物化成虚拟拓扑，做故障注入与状态变更，给出确定性校验和
         前后对比，支持三层撤销（事务回滚 / 变更集逆向 / 检查点）。
   红线：生产设备零写入。

4. AI 拿不到结构化数据
   做法：MCP 工具面 11 个工具（1 检索 + 4 仿真 + 5 只读分析 + 1 费用风险），
         全部参数化只读，调用方永远传不了 SQL。
   附带：告警引擎（阈值 + 维护窗口抑制 + 根因/次生分诊 + 抖动治理 + webhook）、
         定时巡检、质量报告、OpenAPI 自动文档（65 端点，与路由表零漂移）。

5. 费用风险（v0.13 起）
   电费 / 铁塔租费 / 修理费 / 综维费。
   做法：SQLite 状态层 + Parquet 分区大表 + DuckDB 分析引擎。
   六场景：退租后仍在计费 / 跨批次重复结算 / 合同账单金额差异 / 电费环比异常上涨 /
           同类站单位成本离群 / 零资源计费。输出线索 + 阈值 + 行级证据锚点。
   纪律：账单存在 != 重复付款认定，只给待核实线索，不下结论。


[PCDN 工具解决的四个问题]

1. 每天人工跨两个内网系统搬数据
   原流程：登录（含验证码）-> 导出 3-4 张报表 -> Excel 筛选 -> 拼名单 -> 上传封禁。
   现在：一键导出 -> 自动筛选 -> 自动生成 AIOBS 名单 -> 预检 -> 上传 -> 下载结果。

2. 图形验证码挡住自动化
   验证码是蓝色数学算式（如 9-3=?），答案不在前端暴露。
   做法：专用识别器（蓝通道分割 + 断开粘连 + 连通域分块 + 模板匹配 + 算式纠错）。
         真实样本 10/10 全对，同源 95%。
   退路：登录一次保存会话（Token/Cookie 长期有效），日常 daemon 全自动不碰验证码。

3. 封禁操作危险
   做法：预检 + 双重确认 + 处置工作台（待处理池本地持久化、状态机、备注、失败回写、
         导出上门名单给现场工程师）。

4. 业务另一面：解封
   第三方系统没有解封按钮，恢复权限靠白名单（群障告警白名单 / 光猫重启白名单）。
   相关接口已完成逆向分析并存档。

交付：v2.1.3 -> v2.6.0 桌面版 + v3.0 Web 版，体积优化 467MB -> 293.7MB（-37%）。
     本质是把需要工程师现场鼓捣的脚本，做成办公台式双击能用的工具。

--------------------------------
三、能做什么（能力清单）
--------------------------------

NetOps Lab
  · 数据导入：Excel 台账 + PTP 配置脚本，列映射确认，行级记账，幂等与回滚
  · 确定性校验：E/W/I 规则，同输入同输出，可重算
  · 资源检索：32 类资源 / 29 种关系，多条件筛选，CSV/Excel 导出
  · 拓扑可视化：L0-L6 图层画布，物理/逻辑/业务关系分层，2D/3D 地理视图
  · 影响分析：沿依赖方向追溯，受影响与候选根因分离，深度与节点数硬上限防环
  · 仿真工作台：故障注入 / 状态迁移，确定性校验，三层撤销，检查点
  · 告警巡检：阈值规则，定时巡检，维护窗口抑制，根因/次生分诊，抖动治理，webhook
  · 质量报告：按批次/范围出报告（HTML/JSON），证据可追溯
  · AI 接入：MCP 11 工具，只读参数化
  · 费用风险：导入 -> 快照 + Parquet -> 六场景线索 + 行级证据，费用-资源分级关联
  · 运维面：写操作令牌门禁，整库在线备份，OpenAPI 自动文档，Windows 一键运行

PCDN 自动化工具
  · 会话管理：一次登录保存 Token/Cookie，日常免验证码
  · 报表导出：一键导出 IDC 流量报表到按日期归档目录
  · 异常筛选：按日期范围筛选，按流量降序
  · 名单生成：生成 AIOBS 批处置名单（账号|0，PCDN 属性）
  · 批量处置：预检 -> 上传 -> 下载结果，失败自动回写待处理池
  · 处置工作台：Excel 导入 -> 预览勾选 -> 待处理池 -> 一键处置 -> 导出上门名单
  · 验证码识别：专用识别器，回退 OCR，模板库可扩充
  · 定时流水线：daemon 常驻按间隔全自动
  · 多形态：桌面 GUI（exe 免环境）/ CLI / Web 版 / 浏览器插件

--------------------------------
四、技术取向对比
--------------------------------

               NetOps Lab                    PCDN 工具
面对的系统     自建（SQLite 本地库）         别人的（内网 IDC/AIOBS/诊断）
技术路线       Go 单二进制 + React + DuckDB  Python + PyInstaller + OCR
核心难点       数据建模、确定性、AI 可读    逆向接口、验证码、交付易用性
数据方向       只读 + 仿真（零生产写入）     有写权限 -> 需预检 + 确认
合规姿态       不推断关系、不碰生产设备      预检、小批量试、留痕
交付对象       开发 / 架构 /（远期）运营     一线综维人员（双击即用）

同一套问题意识的两种解题姿势：
一个用工程化方式重建数据底座，一个用逆向 + 自动化接管既有系统的重复劳动。

--------------------------------
五、共同的方法论
--------------------------------

1. 确定性优先：同一输入必须产出同一结果（时间戳来自数据而非服务器时钟）
2. 账本意识：每次导入、检测、处置都留行级/批次级回执，失败也留痕
3. 可撤销：改动必须能退（三层撤销 / 待处理池回写 / 会话可重建）
4. 红线显式化：能做什么不能做什么写进文档（零生产写入、关系不推断、账单存在 != 认定）
5. 降级要诚实：能力不具备时给明确错误并附解法，绝不静默返回空数据
6. 给机器留接口：MCP / CLI JSON / OpenAPI，让 AI 和人用同一套事实

--------------------------------
六、适用范围与边界（如实说明）
--------------------------------

NetOps Lab
  · 面向 IPRAN / 传输网的资源治理与影响分析，数据源是网管导出的 Excel 台账
  · 演示数据来自互联网公开数据（OSM 局站/道路、OpenCelliD 基站）+ 模拟派生，
    非运营商真实数据
  · 不具备生产设备写能力，仿真仅限本地工作台
  · 费用分析层需 DuckDB 构建（Windows 原生暂不可用，走 Docker/WSL2）

PCDN 工具
  · 强依赖特定三个内网系统（IDC 流量监测 / AIOBS 批处置 / 端到端诊断群障告警）
  · 需云脉 VPN 才能访问内网
  · 验证码识别依赖模板库，样本越多越准
  · 封禁是有真实影响的操作，必须有预检和人工确认

--------------------------------
七、一句话收尾
--------------------------------

这两个项目做的事，本质是把运维人员从「系统之间的搬运工」变回「判断者」——
让机器去跑那些重复的、格式化的、容易漏的环节，把需要经验与责任的部分留给人。
